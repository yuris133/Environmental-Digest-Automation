# GOTCHAS — грабли проекта (актуально на 18.11.2026)

Собранные на практике подводные камни. Подтверждены реальными инцидентами, не теория.

## RSS-лента и SMMplanner Репостер

1. **Репостер дедуплицирует по guid.** Обновить уже забранный пост (добавить картинку, поправить текст) можно только **новым guid** (суффикс `-2`, `-3`…) — обновление pubDate одно не срабатывает (проверено 18.11: guid -2 со свежим pubDate Репостер не взял).
2. **Свежесть — 1 час.** Репостер по умолчанию игнорирует материалы, у которых pubDate старше часа. Поэтому: любая поздняя правка позиции = новый guid + свежий pubDate + деплой.
3. **Процедура перепоста (полная):** правка item в `feed.xml` (guid + pubDate + правки) → синхронный guid в `rss-site/state.json` → `deploy-feed.ps1` → проверка «Репостер → История» в течение часа → лишние дубли в сетях удалить руками.
4. **`UNABLE_TO_DOWNLOAD_ATTACHMENT`** — Репостер взял пост, но не смог скачать файл картинки. Причина у нас: региональный фильтр `*.pages.dev` у российских операторов «мигает» (то же у серверов SMMplanner). Повтор запуска часто проходит; системное решение — свой домен для Pages (Cloudflare отдаёт кастомный домен без фильтра на имя).
5. **Признак деплоя ≠ доступность домена.** Успех деплоя — «✨ Deployment complete» от wrangler (он работает через `api.cloudflare.com` и не зависит от фильтра). GET-запрос к `pages.dev` с локальной машины может падать по SSL (curl exit 35) даже при живом деплое. Репостер забирает ленту со своих серверов, а не с твоего ноутбука.
6. **`.webp` — рискованный формат** в `<enclosure>`: парсер/сеть могут не принять. Предпочтение jpeg; сегодня webp ещё в ленточных постах от 13 и 17 ноября.
7. **Instagram:** без картинки пост не публикуется — в Репостере нельзя отключать перенос изображений.
8. **Enclosure без `length`:** headless-подготовщик не всегда знает точный размер файла — атрибут дозаполняет `deploy-feed.ps1` из локального файла. Не выдумывать байты.
9. **BASE_URL плейсхолдер `CHANGE-ME`:** лента готовится, но ссылки в ней нерабочие — предупреждать в отчётах, пока не задан.

## Headless-режим (`claude -p`)

10. **Авторизация только через `.claude\auth-weekly.env`;** `/login` интерактивной сессии на headless не влияет. Смок-тест — `scripts\test-headless.cmd`.
11. **fal MCP недоступен headless-сессиям и субагентам** (с 07.11.2026): они не могут сгенерировать картинку — отсюда родился случай 18.11, когда ежедневный пост ушёл в ленту без enclosure. Если готовой картинки нет — пост всё равно готовится, а картинку докидывают в основную сессии (post-illustrator) и потом перепост по п.3.
12. **Сбой расписания** (запуск в 10:59 вместо 10:30 — машина была выключена) сдвигает весь день: pubDate всё равно ставится «свежим», но окно Репостера не ждёт.

## Telegram и VK (прямые цепочки, не SMMplanner)

13. **VK user-token IP-привязан:** `error 5` = токен умер/переехал, перевыпуск через vkhost; токен лежит в `posts news\user_id.env` (gitignored).
14. **group_id в запросах без минуса.**
15. **С 08.11.2026 VK — режим «в обе стены»** (личная стена + стена сообщества); публикацию в сообщество через VK API заменил Репостер SMMplanner (с 12.11) — фото прикрепляет сам, дубли облачных скриптов не нужны.
16. **Telegram: текст с картинкой ≤1024 символов.**
17. **Postiz-цепочки (если используете):** VK без медиа, у TG лимит как выше, в bash-скриптах не интерполировать строки, где `$` в тексте поста (превращается в переменную), id каналов — из настроек Postiz.
18. **В навыке SMMplanner RSS Post не совмещать** Postiz/VK/TG-логику — у поста может быть только один отправитель.

## Файлы и содержимое

19. Существующие отчёты/дайджесты/позиции ленты **не перезаписывать** — суффикс `-2`, `-3` (по формуле нейминга).
20. Тексты JSON-постов из `posts news/` — **утверждённые**: дальше по цепочке (лента, SMMplanner) их не переписывать.
21. Все факты и цифры постов — только из отчёта выпуска; ссылка на источник обязательна.
22. Фото к дайджестам — из источников с подписью-атрибуцией; недоступен источник → SVG-схема в палитре шаблона в палитре шаблона и пометка в отчёте.
23. PDF дайджеста не делает агент — руками в Obsidian.
24. Секреты — только в gitignored env; проверка перед публикацией в git: `git check-ignore` по всем `*.env`, скан истории и коммит-листа на паттерны токенов.
